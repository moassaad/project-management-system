### Fixed
- [BE-BUG-AUTH-01] CORS headers missing on 401/403 auth error responses — root cause: standalone `CorsFilter` bean runs after the Spring Security chain, which the entry point short-circuits on 401 (reproduced via `curl -i` with `Origin`: no `Access-Control-Allow-Origin` on 401). Fix: `CorsConfig` now exposes `CorsConfigurationSource`, wired into the chain via `http.cors()` so Security's CORS filter runs before auth checks and stamps all responses including 401/403. Verified via curl: 401 + 200 (`/me` with Bearer) both carry `Access-Control-Allow-Origin http://localhost:5173` + `Allow-Credentials`; `SecurityFilterTest` +3 (401 CORS on `/me` + `/projects`, 200 CORS). No contract change.
- [BE-DASH-REFRESH-01] Conditional Secure cookie for refresh token — root cause: `AuthController` hard-coded `Secure=true` dropped by browsers on local HTTP dev (refresh never sent back, bootstrap 401 → dashboard empty after refresh). Fix: `app.auth.refresh-cookie-secure` (`${REFRESH_COOKIE_SECURE:true}`, `true` prod / `false` local via `application-h2.yml` + `application-dev.yml`), injected into `AuthController` and applied to all refresh cookies (login/refresh/logout). Verified: `verify` 144 PASS; curl: `h2` profile `Set-Cookie` without `Secure`, default profile with `Secure`.
