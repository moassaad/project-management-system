# Changelog

All notable changes to the React frontend (`frontend-react/`) are documented here.

## Unreleased

### Added
- [FE-S003-01] Established feature-based application structure (`src/app`, `src/features` placeholders, `src/components`, `src/lib`, `src/config`) with `main.tsx` delegating to `AppProviders` and `src/app/App`.
- [FE-S003-02] Added typed environment configuration (`config.apiUrl` from `VITE_API_URL` with dev fallback and validation) and `.env.example`; `.env` files are git-ignored.
- [FE-S003-03] Added centralized routing with React Router v8 (`react-router` package): public `/login`, protected `/dashboard`, `/projects`, `/projects/:projectId`, `/projects/:projectId/tasks/:taskId` placeholders, UX-only guards, `/` redirect and 404 handling; demo `App` replaced by `RouterProvider`.
- [FE-S003-04] Added application providers layer: `QueryClient` (`retry:1`, `staleTime:30000`, `refetchOnWindowFocus:false`) at `src/lib/queryClient.ts` composed via `QueryClientProvider` in `src/app/providers/index.tsx`; `src/main.tsx` delegates to `AppProviders` → `RouterProvider` with intentional ordering.
- [FE-S003-06] Added Zustand shared client state foundation (`zustand@^5`): memory-only `accessToken` with derived `isAuthenticated`, actions `setAccessToken`/`clearAuth` at `src/lib/store/auth-store.ts` (re-exported at `src/features/auth/store/auth-store.ts`); ownership rule documented (Server→Query, Local→useState, Shared→Zustand), anti-duplication noted, no persistence.
- [FE-S003-05] Added shared HTTP infrastructure (`axios` + `@tanstack/react-query` already present): `src/lib/http/client.ts` with `baseURL` from `config.apiUrl`, `Content-Type: application/json`, `Authorization: Bearer <token>` placeholder (memory via Zustand), `withCredentials:true`, RFC 9457 passthrough; feature API example `src/features/projects/api/projects.api.ts` (`listProjects()` stub) and `useHealthQuery` for `GET /api/v1/health` (server-state via Query); ESLint rule enforces no direct `fetch`/`axios` in components.
- [FE-S003-07] Added UI foundation with Tailwind CSS (`tailwindcss@3.4`, `postcss`, `autoprefixer`, `tailwind.config.js`, `postcss.config.js`, `src/index.css` with `@tailwind` directives): primitives `src/components/ui/Button`, `Input`, `Card`, `Layout` (Tailwind, semantic, aria, keyboard navigable); `src/app/App.tsx` layout wraps routes with header/sidebar placeholder navigation to `/dashboard`, `/projects`, `/login` (integrated as parent route in `src/app/router/index.tsx`).
- [FE-S003-08] Established frontend testing foundation (Vitest + RTL + MSW, behavior-focused): `vitest`, `@testing-library/react`, `@testing-library/jest-dom`, `@testing-library/user-event`, `jsdom`, `msw` added; `vite.config.ts:test` (`environment: jsdom`, `setupFiles: ./tests/setup.ts`), scripts `npm test` (`vitest run`) / `npm run test:watch`; `tests/setup.ts` (jest-dom, MSW `setupServer`), `tests/mocks/server.ts`/`handlers.ts` with `GET /api/v1/health` (Axios + TanStack Query compatible); sample tests — unit (`src/utils/format.test.ts`), component (`Button` behavior, `src/components/ui/Button.test.tsx`), integration (`useHealthQuery` + MSW, `src/features/projects/api/useHealthQuery.test.tsx`) — all pass; CI-friendly `tsc -b` + `lint` green.
- [FE-S004-01] Auth API layer, types, and Zod schemas (contract-only, no UI): types `User`, `LoginRequest/Response`, `RefreshResponse`, `AuthState` at `src/features/auth/types/auth.types.ts` (UUID string, camelCase, OpenAPI-aligned); `loginSchema` (`email.email`, `password.min(1)`) at `src/features/auth/schemas/login.schema.ts` (Zod); API layer `src/features/auth/api/auth.api.ts` (`login`, `refresh`, `logout`, `me`) via shared `httpClient` (`withCredentials:true`, `baseURL` from `config.apiUrl`); Query keys `authKeys` at `auth.queries.ts`; MSW handlers extended for `POST /auth/login|refresh|logout` and `GET /auth/me` (Axios+Query compatible).
- [FE-S004-02] Login page UI with RHF+Zod and Zustand store: updated `src/lib/store/auth-store.ts` (and `src/features/auth/store/authStore.ts`) to store `user` + `accessToken` (memory-only, `setAuth(user,token)`/`clearAuth`, `isAuthenticated` derived, no localStorage); hook `src/features/auth/hooks/useLoginMutation.ts` (TanStack Mutation, no duplication); page `src/features/auth/pages/LoginPage.tsx` at `/login` (public) with `useForm`+`zodResolver(loginSchema)`, `email`/`password` fields, `useLoginMutation` → `setAuth` → `navigate('/dashboard')`, loading/error via ProblemDetails `detail`/`title`; routed via `src/app/router/index.tsx` (real `LoginPage` replaces placeholder), no direct Axios in component.
- [FE-S004-03] Axios auth interceptor and refresh flow: extended `src/lib/http/client.ts` with `withCredentials:true` + request `Authorization: Bearer` from Zustand memory + response 401 interceptor (skip `/auth/refresh` & `/auth/login`, `_retry` guard, raw refresh client `POST /auth/refresh` with cookie auto-sent, single refresh for concurrent 401 queue via `failedQueue`, success updates `accessToken` + retries original, failure clears auth + redirects to `/login`; never reads refresh cookie via JS, ProblemDetails handled via `status`/`type` not `detail` string); MSW tests `src/lib/http/client.refresh.test.ts` (401→refresh→retry, concurrent queue single refresh, refresh failure→logout/redirect, login 401 not retried).
- [FE-S004-04] Protected/public route guards and auth bootstrap: updated `src/app/router/protected-route.tsx`/`public-route.tsx` to use Zustand `isAuthenticated`+`isBootstrapping` (UX-only, backend authoritative, loading splash `aria-label=Loading`); central `src/app/router/index.tsx` keeps `/login` public, `/dashboard`/projects protected; `src/features/auth/hooks/useAuthBootstrap.ts` attempts `POST /auth/refresh` (cookie `withCredentials`, never JS) → `GET /auth/me` → `setAuth` on app load, `clearAuth` on 401, `isBootstrapping` splash in `src/app/App.tsx` (`aria-label=Loading application`); `src/features/auth/hooks/useLogoutMutation.ts` (`logout` → `clearAuth` → `navigate('/login')` with `withCredentials`); `src/lib/store/auth-store.ts` added `isBootstrapping`/`setBootstrapping` + `user`; `src/app/App.tsx` shows header/sidebar `Logout` button when authenticated (via `useLogoutMutation`); RTL guard tests `src/app/router/guards.test.tsx` (protected/public + bootstrapping).
- [FE-S005-01] Projects API layer, types, and Query hooks (contract, no pages): types `Project`, `CreateProjectRequest`, `UpdateProjectRequest`, `PaginatedProjects` at `src/features/projects/types/project.types.ts` (UUID, camelCase, OpenAPI); Zod `createProjectSchema`/`updateProjectSchema` at `src/features/projects/schemas/project.schema.ts` (`name min1`, `description` optional); API layer `src/features/projects/api/projects.api.ts` (`listProjects(page,perPage)`, `getProject`, `createProject`, `patchProject`, `deleteProject`) via `httpClient` (Bearer+withCredentials, no component fetch); hooks `useProjectsQuery`/`useProjectQuery`/`useCreateProjectMutation`/`useUpdateProjectMutation`/`useDeleteProjectMutation` at `src/features/projects/hooks/useProjectsQueries.ts` (`projectKeys`, server-state, invalidation); MSW handlers for `GET/POST /projects`, `GET/PATCH/DELETE /projects/:projectId` (paginated, ProblemDetails 404/422, wildcard `*/api/v1/projects*`).
- [FE-S005-02] Project list and details pages: `ProjectsPage` at `/projects` (protected) via `useProjectsQuery` with pagination, loading skeletons, empty state, status-based error + retry; `ProjectDetailsPage` at `/projects/:projectId` via `useProjectQuery` with loading, 404/401/403 handling; centralized router reuse, Tailwind + `Card`/`Button`, semantic/a11y; RTL tests `ProjectsPages.test.tsx` (list/empty/error/details/404 via MSW).
